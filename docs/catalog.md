# Catalog data model

Project Viewer stores everything locally. The backend owns validation and writes; the React frontend only calls Tauri commands and renders the returned catalog.

## Location

Tauri resolves the app data directory from the bundle identifier `com.ian.projectviewer`. On Linux that is normally:

```text
~/.local/share/com.ian.projectviewer/
├── projects.json
├── settings.json
└── covers/
```

In debug builds, `PROJECT_VIEWER_DATA_DIR` can override the directory for isolated tests. This override is ignored in release builds. The asset protocol used to display covers is scoped to the real app data directory, so cover previews require the default data directory (or a production build).

## `projects.json`

```json
{
  "version": 1,
  "projects": [
    {
      "id": "6f4f7d1e-5b2a-4d54-9d5a-2a4d7b1c3e10",
      "name": "Project Viewer",
      "path": "/home/ian/Documents/remote/github/Project-Viewer",
      "cover": "covers/6f4f7d1e-5b2a-4d54-9d5a-2a4d7b1c3e10-1760000000000-ab12cd34.png",
      "status": "active",
      "createdAt": 1760000000000,
      "updatedAt": 1760000000000,
      "archivedAt": null
    }
  ]
}
```

| Field | Type | Notes |
| --- | --- | --- |
| `version` | number | Catalog schema version. Currently `1`. |
| `projects` | array | All projects, active and archived. |
| `id` | string | UUID v4 generated by the backend. |
| `name` | string | Trimmed, 1–80 characters. |
| `path` | string \| null | Canonical absolute directory path, or `null`. |
| `cover` | string \| null | Path relative to the data directory, always inside `covers/`. |
| `status` | `"active"` \| `"archived"` | Archived projects are hidden from the main grid. |
| `createdAt` | number | Epoch milliseconds. |
| `updatedAt` | number | Epoch milliseconds; the active grid sorts by this descending. |
| `archivedAt` | number \| null | Epoch milliseconds when archived; `null` for active projects. |

## `settings.json`

```json
{
  "version": 1,
  "autostartInitialized": true,
  "autostartEnabled": true
}
```

`autostartInitialized` prevents re-enabling autostart after the user disabled it. The actual XDG entry is managed by `tauri-plugin-autostart`; the app refreshes its executable path on startup.

## Validation rules

- **Name:** required after trimming; 1–80 Unicode characters.
- **Path:** optional. When present it must be absolute, exist, be a directory, and is canonicalized with `std::fs::canonicalize`.
- **Duplicate paths:** two **active** projects cannot share the same canonical path. An archived project's path can be reused.
- **Cover:** PNG, JPEG, WebP, or GIF; maximum 5 MB. The file's magic bytes are checked, not just its extension. SVG is rejected.
- **Path deletion:** removing a project never deletes the referenced local folder.

## Cover pipeline

1. The file picker returns an absolute source path.
2. `stage_cover` validates size and magic bytes, then copies the file to `covers/staged-<uuid>.<ext>`.
3. The form previews the staged file through the Tauri asset protocol.
4. On save, the staged file is renamed to `covers/<project-id>-<timestamp>-<suffix>.<ext>`, the catalog is written, and the previous cover is deleted.
5. On cancel, `discard_cover` removes the staged file.
6. On startup, leftover `staged-*` files are removed. Final covers that are not referenced are left alone; a failed catalog write removes the promoted file explicitly.

Unique filenames per revision avoid WebKit caching an old cover after replacement.

## Atomic writes and recovery

Catalog and settings writes use the same sequence:

1. Serialize the JSON.
2. Write to `<file>.tmp`.
3. `fsync` the temporary file.
4. Rename it over the final file.
5. On Unix, `fsync` the directory.

If the catalog cannot be parsed or has an unsupported version, the backend renames it to `projects.corrupt-<epoch>.json`, starts with an empty catalog, and returns a warning to the frontend. A failed write leaves the previous file untouched.

## Error contract

Commands return `{ "code": string, "message": string, "details"?: string }` on failure. The frontend maps codes to Spanish messages.

| Code | Meaning |
| --- | --- |
| `INVALID_NAME` | Empty or too-long project name. |
| `INVALID_PATH` | Relative, missing, or non-directory path. |
| `DUPLICATE_PATH` | Another active project already uses the path. |
| `COVER_UNSUPPORTED` | Not a PNG/JPEG/WebP/GIF or invalid staged cover. |
| `COVER_TOO_LARGE` | Cover larger than 5 MB. |
| `CATALOG_READ_FAILED` | Data/covers directory could not be created. |
| `PROJECT_NOT_FOUND` | Unknown project id. |
| `PROJECT_NOT_ARCHIVED` | Delete requested for an active project. |
| `PATH_UNAVAILABLE` | Project has no path or its folder no longer exists. |
| `TOOL_NOT_FOUND` | `xdg-open`, `code`, or a terminal was not detected. |
| `SPAWN_FAILED` | The tool could not be launched. |
| `INVALID_ACTION` | Action outside `folder`, `vscode`, `terminal`. |
| `AUTOSTART_FAILED` | Autostart could not be enabled/disabled, or was requested in dev mode. |
| `INTERNAL` | Unexpected filesystem or serialization failure. |

## Tests

- Rust: `cd src-tauri && source ~/.cargo/env && cargo test` covers serialization, atomic writes, corruption recovery, validation, duplicates, cover handling, action argument construction, and autostart preference logic.
- Frontend: `npm run test` covers the catalog hook, grid, form, menu, archived view, settings toggle, and integration flows.
